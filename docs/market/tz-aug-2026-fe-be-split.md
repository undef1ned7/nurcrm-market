Документ фиксирует, какие доработки из ТЗ можно закрыть только на фронте, а где обязателен бэкенд (или согласование API).

Стек фронта: React 18 + Vite + Redux (FSD). Текущие API: `/main/...`, `/warehouse/...` (не `/api/v1/...` из ТЗ).

## Модуль 1. Массовое добавление товаров на склад

**Итог: нужен Backend.** Frontend без BE не проведёт атомарный приход и корректную классификацию штрихкодов.

### Frontend (можно готовить параллельно)

- Кнопка «Массовое сканирование» в разделе «Склад»
- Полноэкранный UI, автофокус + возврат фокуса через 1 с
- Три списка (IN_STOCK / IN_CATALOG / UNKNOWN), debounce 300 ms, звуки
- Ручное редактирование количества
- Модалка «Создать карточку» с подставленным штрихкодом (после create — миграция в список 2)
- Предупреждение при закрытии без сохранения

### Backend (обязательно)

| Endpoint / задача | Назначение |
|-------------------|------------|
| Проверка штрихкода (аналог `barcode-check`) | Статус: на текущем складе / в каталоге / неизвестен + данные товара |
| Атомарный `mass-incoming` | Проведение прихода по спискам 1 и 2 одним документом |
| Создание карточки по штрихкоду | Уже частично есть (`scan` / create-by-barcode) — уточнить контракт |

**Уже есть на FE/API (переиспользовать):**  
lookup barcode, `POST warehouse/{uuid}/products/scan/`, документы прихода (`createReceiptDocument`).

**Риск без BE:** частичный успех при построчном сохранении → рассинхрон остатков.

## Модуль 2. Интерактивный центр уведомлений

**Итог: смешанный.** Каркас уже есть; полный ТЗ без BE не закрывается.

### Frontend only (можно сделать сразу)

- Красный бейдж со счётчиком непрочитанных на иконке колокольчика
- Кнопка «Отметить все как прочитанные» / удаление — если API уже поддерживает (mark-all-read есть)
- Полировка выпадающей панели

### Backend (нужен для полного ТЗ)

| Задача | Зачем |
|--------|--------|
| Категории: тариф / системные / новости | Вкладки «Все», «Тариф», «Системные» |
| Автоалерты тарифа за 7 / 3 / 1 день | Контент вкладки «Тариф» + CTA «Продлить» |
| Сервисные уведомления (техработы, рестарты) | Админская/системная публикация |
| Новости и акции | Контент для «Новости» |
| Удаление уведомления (если нет в API) | Действие «удалить» в UI |
| Фильтр по типу в `GET /main/notifications/` | Работа вкладок без клиентской эвристики |

**Уже есть:** bell, `NotificationModal`, REST, WebSocket `/ws/notifications/`.

## Модуль 3. Второй экран покупателя

**Итог: в основном Frontend.** Backend не обязателен для MVP.

### Frontend only

- Тумблер «Включить второй экран» + «Открыть окно» в настройках кассы
- Отдельный route / окно для 2-го монитора
- Синхронизация через `BroadcastChannel` (или `localStorage` events)
- Режимы: ожидание (лого + приветствие + слайдер), корзина, завершение («Спасибо»)
- Список позиций, кол-во, цена, скидка, крупный итог

### Backend (опционально)

| Задача | Когда нужен |
|--------|-------------|
| Сохранение приветствия / слайдов акций на сервере | Если настройки общие для сети магазинов / нескольких касс |
| QR на оплату | Только при готовой платёжной интеграции |

**Рекомендация MVP:** FE + localStorage/настройки компании уже на клиенте; QR и серверные слайды — фаза 2.

## Модуль 4. Горячие клавиши быстрых продаж (F3 + 0..9)

**Итог: Frontend достаточен для MVP.** Backend желателен для продакшена.

### Frontend only (MVP)

- `preventDefault` на F3, режим «ожидание цифры»
- Цифры 0–9 / Numpad → +1 товара в корзину
- Конструктор привязок слотов 0–9 (UI)
- Бейджи `[F3 + N]` на кнопках быстрых товаров
- Хранение слотов в `localStorage` на устройстве кассы

### Backend (желательно)

| Задача | Зачем |
|--------|--------|
| API слотов быстрых товаров (0–9 → product_id) | Одинаковые привязки на всех кассах / после смены ПК |
| Миграция / сосуществование с `hotkey_group` (F1–F12) | Сейчас уже есть группы F1–F12 — нужно продуктовое решение |

**Важно:** текущая модель (F1–F12 → модалка группы) ≠ ТЗ (F3 + цифра → сразу в чек). Решение «заменить / дополнить / только внутри F3» — до старта разработки.

## Модуль 5. Денежный ящик (Zadig / ESC-POS)

**Итог: только Frontend.** Backend не нужен.

### Frontend only

- Блок настроек «Денежный ящик» в POS print settings
- Тумблер «Открывать при печати чека»
- Тайминг: до / после печати
- Поле кастомной ESC/POS команды (default `27, 112, 0, 25, 250`)
- Кнопка «Проверить открывание ящика»
- Отправка kick через существующий WebUSB / printer-bridge (`printService.js`)

**Уже есть:** ESC/POS печать, Zadig-подсказки, `/crm/pos-print-settings`.

## Порядок работ без ожидания бэка

Можно стартовать сразу на FE:

1. **Модуль 5** — денежный ящик  
2. **Модуль 3** — второй экран (MVP без QR)  
3. **Модуль 2** — бейдж на колокольчике  
4. **Модуль 4** — F3+0..9 на localStorage (после решения по F1–F12)

Ждать / параллелить с BE:

1. **Модуль 1** — `barcode-check` + `mass-incoming`  
2. **Модуль 2** — категории, тарифные джобы, новости  
3. **Модуль 4** (фаза 2) — серверные слоты
