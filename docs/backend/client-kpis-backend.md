# Маркет — KPI карточки клиента

**Экран:** `/crm/clients/:id` (карточка клиента)  
**Фронт:** `src/pages/clients/ui/ClientDetails/` + `src/entities/client/api/clientKpis.ts`  
**Эндпоинт:** `GET /main/clients/{id}/kpis/`  
**Статус:** фронт готов; бэкенд отсутствует. При ошибке (`404`/`405`/сеть) фронт временно считает те же цифры по `GET /main/clients/{id}/deals/`.

Связанные эндпоинты:

| Метод | Путь | Зачем |
|---|---|---|
| `GET` | `/main/clients/{id}/` | карточка клиента |
| `GET` | `/main/clients/{id}/deals/` | список сделок (таблица и drawer, не KPI) |
| `POST`/`PATCH`/`DELETE` | `/main/clients/{id}/deals/` | после изменения сделок KPI должны пересчитаться |
| `POST` | `/main/clients/{id}/deals/{dealId}/pay/` | погашение долга меняет `remaining_debt` |
| `GET` | `/main/pos/sales/?client=` | история чеков кассы — **не** входит в эти карточки |

---

## Purpose

На карточке клиента три KPI:

1. **Общий долг**
2. **Аванс**
3. **Продажи**

Сейчас фронт тянет все сделки и суммирует на клиенте. Это медленно и расходится, если deals пагинированы. Считать должен бэк: один запрос → три суммы и три счётчика.

---

## Endpoint

```http
GET /main/clients/{client_id}/kpis/
Authorization: Bearer <access_token>
```

Почему этот path:

- KPI живут в контексте клиента, рядом с `/deals/`;
- не раздуваем `GET /main/clients/{id}/` (его дергают касса, склад, список);
- фронт вызывает **этот** URL. Если выберете другой — напишите, путь меняется в `CLIENT_KPIS_URL`.

Не использовать `/api/v1`.

Доступ: любой сотрудник компании, который видит этого клиента. Чужой `client_id` → `404`.

---

## Ответ 200

```json
{
  "debt": { "amount": "1200.50", "count": 2 },
  "prepayment": { "amount": "300.00", "count": 1 },
  "sale": { "amount": "4500.00", "count": 4 }
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `debt.amount` | decimal string | остаток долга, сом |
| `debt.count` | int ≥ 0 | число сделок-долгов |
| `prepayment.amount` | decimal string | сумма авансов / предоплат |
| `prepayment.count` | int ≥ 0 | число сделок, из которых сложился аванс |
| `sale.amount` | decimal string | сумма продаж (сделки `kind=sale`) |
| `sale.count` | int ≥ 0 | число таких сделок |

`amount` — строка с 2 знаками (`"0.00"`), как в deals. `count` — целое.

Нет сделок:

```json
{
  "debt": { "amount": "0.00", "count": 0 },
  "prepayment": { "amount": "0.00", "count": 0 },
  "sale": { "amount": "0.00", "count": 0 }
}
```

Всегда отдавать все три ключа. Extra-поля — **не 400**, фронт их игнорирует.

Опционально можно обернуть в `{ "kpis": { ... } }` — фронт это поймёт. Канон — плоский объект с `debt` / `prepayment` / `sale`.

---

## Формула (обязательно совпасть с этим)

Считать **только deals** клиента (`/main/clients/{id}/deals/`).  
**Не** включать POS-чеки `/main/pos/sales/`.  
**Не** фильтровать по дате: карточки над фильтром списка, это итог по клиенту целиком.

`kind` сделки: `"debt"` | `"prepayment"` | `"sale"`. Нет `kind` → `"sale"`.

### `debt`

- `amount` = сумма `remaining_debt` по сделкам `kind = "debt"`
- `count` = число сделок `kind = "debt"` (включая с нулевым остатком)

`remaining_debt` — текущий остаток после оплат, не исходный `amount`.

### `prepayment`

- `amount` = сумма `prepayment` по `kind = "debt"`, где `prepayment > 0`  
  **плюс** сумма `amount` по `kind = "prepayment"`
- `count` = число сделок, которые вошли в сумму (долг с предоплатой > 0 **или** `kind = "prepayment"`)

Не путать: у долга в сумму аванса идёт поле `prepayment`, не весь `amount`.

### `sale`

- `amount` = сумма `amount` по сделкам, которые не `debt` и не `prepayment`
- `count` = число таких сделок

Считать в центах/тийинах, в ответ — 2 знака. Пример: `70.00 + 0.10` → `"70.10"`, не float-мусор.

---

## Когда пересчитывать

KPI — денормализованный снимок **или** live-агрегат, на выбор бэка. Главное: после этих событий ответ меняется без ручного рестарта:

- `POST /deals/` (продажа / долг / предоплата)
- `PATCH /deals/{id}/`
- `DELETE /deals/{id}/`
- `POST /deals/{id}/pay/` (остаток долга)
- refund по сделке, если есть

Касса после отсрочки создаёт deal — карточка клиента должна увидеть новый долг.

---

## Ошибки

| Случай | HTTP |
|---|---|
| нет клиента / чужая компания | 404 |
| не авторизован | 401 |
| неизвестное extra-поле в будущем | **не 400** |

Нет отдельного `400` на «нечего считать» — отдаём нули.

---

## Опционально (не блокер)

Можно дублировать тот же объект в `GET /main/clients/{id}/` как `kpis`. Фронт **пока не читает** его оттуда, ходит в `/kpis/`.

Не нужно:

- фильтр `date_from` / `date_to` (карточки — итог за всё время);
- список сделок внутри KPI (drawer берёт `/deals/`);
- POS-продажи в `sale`.

---

## Критерии приёмки BE

- [ ] `GET /main/clients/{id}/kpis/` отдаёт три ключа `debt` / `prepayment` / `sale`.
- [ ] Долг: `amount` = сумма `remaining_debt`, не исходных `amount`.
- [ ] Аванс: предоплата с долговых сделок + сделки `kind=prepayment`.
- [ ] Продажи: только deals `kind=sale`, без POS.
- [ ] Нет сделок → все `"0.00"` и `0`.
- [ ] После `pay/` долг уменьшается в KPI без рассинхрона со списком deals.
- [ ] Пагинация `/deals/` не влияет на KPI (считать по всем сделкам клиента).
