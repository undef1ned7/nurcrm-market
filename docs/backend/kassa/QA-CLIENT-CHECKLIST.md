# QA: клиентский прогон на staging

**Когда:** после выката BE (`AUTO_CASHFLOWS=true`) + FE (`VITE_BE_CASHFLOWS=true`)  
**Кто:** QA или кассир + складской на тестовой компании  
**Длительность:** ~40 минут

См. также: [SCENARIO-POST-MIGRATION.md](./SCENARIO-POST-MIGRATION.md), [shift-cash-reconciliation-backend.md](./shift-cash-reconciliation-backend.md)

---

## Предусловия

| # | Проверка |
|---|----------|
| 1 | На компании 5 касс с `role`: `pos_main`, `pos_branch`, `expense_variable`, `expense_fixed` |
| 2 | `AUTO_CASHFLOWS=true` (BE), `VITE_BE_CASHFLOWS=true` (FE) |
| 3 | DevTools → Network, фильтр `cashflows` — для авто-операций **нет** лишних `POST /construction/cashflows/` |
| 4 | Нет открытой смены перед стартом |

## A. Золотой кейс (регрессия expected_cash)

| # | Действие | Ввод | Pass |
|---|----------|------|------|
| A1 | Открыть смену | размен **50** | Смена open, POS-касса |
| A2 | Продажи **наличными** | сумма **33 768** | `cash_sales_total ≈ 33768` |
| A3 | Закупка / приход поставщика | **54 625** наличными | Без выбора кассы в UI |
| A4 | Закрыть смену | факт **8 888** | См. таблицу |

**Ожидаемые цифры:**

| Поле | Значение |
|------|----------|
| `expected_cash` / drawer expected | **33 818** (50 + 33 768) |
| `cash_diff` | **−24 930** (8 888 − 33 818) |
| Закупки | **не** уменьшают expected |

**Fail:** `expected_cash = −20 806` или `cash_diff = +29 694`.

## B. POS (касса)

| # | Действие | Pass |
|---|----------|------|
| B1 | Продажа наличными | Успех; **нет** dropdown кассы |
| B2 | Оплата долга **клиента** | Успех без «Выберите кассу» |
| B3 | Продажа **без** открытой смены | Понятная ошибка (не silent success) |
| B4 | Network после B1–B2 | Business POST есть; FE `POST /cashflows/` **нет** |

### C1. Клиент нам платит

```
Касса → Оплатить долг → клиент → взнос (наличные)
```

| Pass |
|------|
| Долг уменьшился |
| `expected_cash` / drawer вырос (или учтено в cash sales) |
| Cashflow: `debt_repayment`, income, POS-касса |

### C2. Мы платим поставщику

```
Клиенты → поставщик → долг → оплатить
```

| Pass |
|------|
| Долг поставщику уменьшился |
| **`expected_cash` смены не изменился** |
| Cashflow: `supplier_debt_payment`, expense, `expense_variable` |

## E. Закрытие смены

| Элемент | Pass |
|---------|------|
| «Ожидаемо по продажам» | opening + cash_sales |
| `expected_cash` API | = drawer expected |
| `payment_breakdown` | Массив `[]` или строки; **не** `null` |
| Split-чек | Одна строка «Смешанная» |
| Отменённый чек | Не в breakdown |

## F. Anti-double

| Действие | Pass |
|----------|------|
| Одна продажа | Одна auto-запись в кассе |
| Двойной клик «Оплатить» | Один cashflow (idempotency) |
| Reject в Pending | Откат sale без ручных действий |

## G. Ручная касса

```
/crm/kassa → ручной приход/расход
```

| Pass |
|------|
| Пользователь **сам** выбирает кассу — норма |
| Auto-операции не дублируют ручную запись |

---

## Красные флаги (stop release)

1. Expected **−20 806** при кейсе A — формула BE не выкатилась  
2. **Два** cashflow на одну продажу — double-write FE+BE  
3. Оплата **поставщику** меняет expected смены  
4. Продажа **без смены** проходит молча  
5. Закупка блокируется «нет касс» / требует POS-кассу  
6. `payment_breakdown: null` в API

## Быстрый чек-лист

```
□ A: 50 + 33768 − закупки 54625 → expected 33818, diff −24930
□ B: продажа и долг клиента без picker кассы
□ C1: долг клиента → ящик
□ C2: долг поставщику → ящик не меняется
□ D: склад без picker кассы
□ E: payment_breakdown корректен
□ F: нет double cashflow
□ G: ручная /crm/kassa работает
```
