# Маркет — разбивка смены по способам оплаты

**Страницы:** закрытие смены на кассе (`/crm/market/cashier` → «Закрыть смену»), карточка смены `/crm/shifts/:id`  
**Статус:** фронт готов; **бэкенд готов** — поле `payment_breakdown` в ответе смены.

Связанные эндпоинты:

| Метод | Путь | Зачем |
|---|---|---|
| `GET` | `/construction/shifts/<id>/` | детали смены, сейчас: `cash_sales_total`, `noncash_sales_total`, `sales_count` |
| `POST` | `/construction/shifts/<id>/close/` | закрытие, body `{ closing_cash }`, ответ — обновлённая смена |
| `GET` | `/construction/cash/shifts/<id>/sales/` | продажи смены (фолбэк фронта) |
| `GET` | `/main/pos/sales/?shift=<id>` | запасной фолбэк |

---

## Purpose

При закрытии кассы кассир видит **на какую сумму закрыли** и **каким способом сколько раз оплачивали**.

Сейчас смена отдаёт только две кучи денег: нал / безнал. Этого мало:

- безнал на кассе — это МБанк / Оптима / О-Банк / Бакай / перевод;
- есть **смешанная** оплата (часть онлайн + часть нал);
- есть **отсрочка**.

Нужна разбивка: способ → число чеков → сумма.

---

## Поле `payment_breakdown`

Добавить в объект смены массив. Отдавать в:

- `GET /construction/shifts/<id>/`
- `GET /construction/shifts/` (можно, не обязательно)
- **ответ** `POST /construction/shifts/<id>/close/` — обязательно, это экран «Смена закрыта»

```json
{
  "id": "...",
  "closing_cash": "15200.00",
  "expected_cash": "15000.00",
  "sales_total": "28400.00",
  "cash_sales_total": "18000.00",
  "noncash_sales_total": "8400.00",
  "sales_count": 17,
  "payment_breakdown": [
    {
      "method": "cash",
      "label": "Наличные",
      "count": 9,
      "amount": "18000.00"
    },
    {
      "method": "mbank",
      "label": "МБанк",
      "count": 4,
      "amount": "6200.00"
    },
    {
      "method": "optima",
      "label": "Оптима Банк",
      "count": 2,
      "amount": "2200.00"
    },
    {
      "method": "split",
      "label": "Смешанная",
      "count": 1,
      "amount": "1500.00"
    },
    {
      "method": "debt",
      "label": "Отсрочка",
      "count": 1,
      "amount": "500.00"
    }
  ]
}
```

| Поле | Тип | Описание |
|---|---|---|
| `method` | string | Стабильный код, как в checkout |
| `label` | string | Русская подпись для UI/печати |
| `count` | int ≥ 0 | Сколько **чеков** этим способом |
| `amount` | decimal string | Сумма этих чеков, 2 знака |

Пустой массив `[]`, если за смену не было продаж. `null` не использовать.

Не слать строки с `count=0` и `amount=0`.

---

## Коды `method`

Совпадают с кассой (`POST /main/pos/sales/<id>/checkout/`):

| `method` | Когда |
|---|---|
| `cash` | Наличные |
| `mbank` / `optima` / `obank` / `bakai` / `demir` / `other` | Безнал конкретным банком |
| `transfer` | Безнал без банка (карта/перевод) |
| `card` | Если так уже пишется в старых чеках — оставить, не мапить в `transfer` |
| `split` | Смешанная: `payments` из 2+ разных способов |
| `debt` | Отсрочка (`payment_method=debt` / `deferred`) |

Алиас `deferred` → отдавать как `debt`.

---

## Правила подсчёта

Считать **чеки смены**, не строки `payments`.

1. Статусы `canceled` / `cancelled` / `refunded` / `returned` — **не входят**.
2. Один чек = `count + 1` ровно у одного `method`.
3. Если у чека `payments[]` с **двумя и более разными** `method` — это `split`. `amount` = `sale.total` (не сумма кусков отдельно по банкам).
4. Иначе `method` = `sale.payment_method` (или единственный элемент `payments`).
5. Отсрочка с предоплатой наличными — всё равно `debt` (кассир выбрал отсрочку). Не дробить на `cash` + `debt`.
6. `amount` — итог чека (`total`), 2 знака.
7. `count` смешанных **не** плюсовать в `cash` и `mbank`. Иначе «сколько раз» врёт.

`cash_sales_total` / `noncash_sales_total` **не менять**. Это другие поля (деньги в ящике vs безнал). В `payment_breakdown` смешанный чек целиком в `split`.

Сортировка: по `amount` убыв., при равенстве по `count` убыв.

---

## Совместимость

- Нет поля → фронт сам тянет продажи смены и считает на клиенте (медленно на большой смене).
- Неизвестный `method` — отдать как есть, `label` можно человеческий или сам код.
- `label` желателен; если пустой, фронт подставит свой словарь.

---

## Чек-лист приёмки

Данные: смена из 6 чеков — 3 нал, 1 МБанк, 1 смешанная (нал+МБанк), 1 отсрочка. Отменённый чек в смене есть, в разбивку не входит.

| # | Запрос | Ожидание |
|---|---|---|
| 1 | `GET /construction/shifts/<id>/` | `payment_breakdown` из 4 строк: cash count=3, mbank=1, split=1, debt=1 |
| 2 | `POST .../close/` `{ closing_cash }` | то же поле в ответе, плюс `closing_cash` |
| 3 | Отменённый чек | не в `count` и не в `amount` |
| 4 | Смешанный чек | только `split`, не +1 к cash и mbank |
| 5 | Пустая смена | `payment_breakdown: []` |
| 6 | Старые поля `cash_sales_total` / `noncash_sales_total` | как раньше |
