# Аналитика «Финансы»: детальная разбивка «Прочие расходы»

**Страницы:** `/crm/market/analytics` → таб «Финансы»
**Статус фронта:** реализовано (карточка KPI + отдельная таблица, best-effort filter на клиенте)
**Статус бэка:** требуется реализация
Префикс: `{host}/api` · TZ: **Asia/Bishkek (UTC+6)**

Читать вместе с: [analytics.md](../analytics.md) (общий контракт `tab=finance`), [cashflow-edit-cancel-request-backend.md](./cashflow-edit-cancel-request-backend.md), [auto-cashflows-backend.md](./auto-cashflows-backend.md) (`source_business_operation_id`).

---

## 1. Зачем

В аналитике «Финансы» уже есть агрегированная таблица `tables.expense_breakdown` (статья → сумма → кол-во операций) и плоский список `tables.expense_items` (все расходные операции периода). У статьи **«Прочее»** сейчас нет детализации: владелец видит только общую сумму в `expense_breakdown`, но не может посмотреть, из каких конкретно операций она сложилась.

Просьба клиента: отдельная карточка KPI «Прочие расходы» + отдельная таблица с подробной информацией по каждой операции этой категории (аналог существующей таблицы `expense_items`, но отфильтрованной по статье «Прочее»).

---

## 2. Что уже делает фронт (без бэка, best-effort)

`src/pages/analytics/ui/hooks/analytics/useAnalyticsTabData.ts` → `financeData`:

1. Ищет в `tables.expense_items[]` поле категории по цепочке фолбэков: `category ?? business_operation ?? business_operation_name ?? source_business_operation_id ?? article ?? name` и сравнивает (case-insensitive) со значениями `"прочее"`, `"прочие расходы"`, `"other"`.
2. Если ни одно из этих полей не приходит с бэка отдельно от `name` — фильтр **не сработает** (список останется пустым), т.к. `expense_items[].name` сейчас содержит конкретное описание операции (например, «Закупка товара: Хлеб»), а не статью.
3. Сумму для KPI берёт по приоритету: `cards.other_expense_total` → строка `expense_breakdown`, где `name` = «Прочее» → сумма отфильтрованных `expense_items`.

**Вывод:** карточка KPI уже покажет корректную сумму (т.к. `expense_breakdown` уже группирует по статье «Прочее» — это работает и сегодня). Таблица с детализацией останется пустой, пока бэк не добавит поле категории на уровне отдельной операции (см. §3).

---

## 3. Что нужно от бэка

### 3.1 Поле категории на уровне `expense_items[]` / `income_items[]`

Сейчас (по контракту `analytics.md`, `tab=finance`) `tables.expense_items[]` отдаёт как минимум `id`, `name`, `amount`, `cashbox`, `created_at`, `created_by`, `description`. Нужно добавить поле статьи операции — то, по которому уже группируется `expense_breakdown`:

```json
{
  "id": "93f5e34a-b414-41df-b59f-01231af...",
  "name": "Закупка запчастей для кассового аппарата",
  "category": "Прочее",
  "amount": "1500.00",
  "cashbox": "Основная касса",
  "created_at": "2026-09-04T10:12:00+06:00",
  "created_by": "Айбек",
  "description": "Ремонт принтера чеков"
}
```

Поле называйте `category` (или, если проще — переиспользуйте существующий на бэке `source_business_operation_id`/аналог, но тогда явно сообщите фронту точное имя поля, т.к. фронт уже проверяет несколько вариантов имени как fallback).

Аналогично добавить `category` в `income_items[]`, если в будущем понадобится та же детализация по доходам (сейчас фронт фильтрует только `expense_items`, но структура симметричная — дешевле добавить сразу в оба).

### 3.2 (опционально) `cards.other_expense_total`

Явное поле в `cards` было бы точнее, чем то, что фронт сейчас выводит из `expense_breakdown` (совпадает по смыслу, но лучше не полагаться на совпадение текстовой метки статьи):

```json
{ "other_expense_total": "12450.00" }
```

---

## 4. Что не нужно менять

- `tables.expense_breakdown[]` — уже группирует по статье, ничего менять не нужно, фронт продолжает читать строку «Прочее» оттуда как один из источников суммы.
- Существующие поля `expense_items[]`/`income_items[]` — не переименовывать и не убирать, только добавить `category`.

---

## 5. Тест-сценарии

1. Создать расходную операцию без явной статьи (или со статьёй «Прочее») → `expense_items[]` содержит эту операцию с `category: "Прочее"`.
2. `expense_breakdown[]` строка «Прочее».`total` равна сумме всех `expense_items[]` с `category: "Прочее"` за тот же период.
3. Операция с другой статьёй (например, «Закупки», «Зарплата») → не попадает в фильтр «Прочее» на фронте (проверяется через `category`, а не по факту непустого `name`).
4. `cards.other_expense_total` (если реализовано) совпадает с суммой из п.2.
