# Маркет — раскладка формы создания товара

**Экран фронта:** `/crm/sklad/add-product`  
**Фронт:** `src/features/warehouse-ops/ui/AddProductPage/formLayout/`  
**Эндпоинты:**

- `GET /main/products/form-layout/` — прочитать раскладку компании
- `PATCH /main/products/form-layout/` — сохранить раскладку (owner/admin)

**Статус:** фронт готов; бэкенд отсутствует. При `404`/`405`/`501` фронт молча работает с `localStorage` на этом устройстве. После реализации эндпоинтов раскладка синхронизируется между устройствами автоматически.

Связанные существующие эндпоинты:

| Метод | Путь | Зачем |
|---|---|---|
| `GET` | `/users/company/` | id компании, роль не здесь |
| `GET` | `/users/profile/` | `role` (`owner` / `admin` / сотрудник) |
| `GET`/`PATCH` | `/users/settings/company/` | **не использовать** — жёсткий сериализатор компании |
| `GET`/`PATCH` | `/main/pos/cashier-settings/` | образец singleton-настроек на компанию |

---

## Purpose

Форма создания товара перегружена: характеристики, 18+, акции, долг, срок годности, горячие клавиши и т.д. Владелец магазина должен один раз убрать ненужные поля — как в Control Center на iPhone.

Раскладка **одна на компанию**, не на браузер:

- кассир открыл форму на другом планшете — видит ту же упрощённую форму;
- скрытое поле не удаляет данные товара, только UI;
- если у уже сохранённого товара поле заполнено, фронт всё равно его показывает (чтобы не потерять акцию / 18+ / фото).

---

## Модель данных

Одна запись на компанию (singleton). Предлагаемая модель `MarketProductFormLayout`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid | PK |
| `company` | FK → Company, `unique=True` | Компания-владелец |
| `hidden` | `JSONField`, default `[]` | Список id скрытых блоков формы |
| `updated_at` | datetime | Авто |
| `updated_by` | FK → User, null | Кто последний менял |

Запись создаётся лениво: при первом `GET`/`PATCH` — `get_or_create(company=request.user.company)` с `hidden=[]`.

`hidden=[]` = форма как сейчас, все поля видны.

### Допустимые id (`hidden`)

Фронт знает только этот набор. Неизвестные id клиент **игнорирует**. Новые id в будущих релизах **не** должны автоматически попадать в `hidden` — иначе у магазинов внезапно пропадут новые поля.

```
code, barcode, alternateBarcodes, article, hotkey, images,
category, brand,
unit, pieceSale, weight, adult, packaging,
markup, wholesale, discount,
supplier, debt, minStock, country, expiry,
promotion, characteristics, description, plu
```

Валидация на бэке: каждый элемент — строка из этого списка. Дубликаты убрать. Остальное отбросить (не 400). Так фронт и бэк могут раскатываться независимо.

Нельзя прятать (фронт это гарантирует, бэк может не знать): наименование, количество, цена закупки/продажи, тип товара, кнопки сохранить/отмена.

## Контракт API

Базовый префикс: `{host}/api`. Не вводить `/api/v1/`.  
Авторизация: `Authorization: Bearer <accessToken>`.

Почему этот path:

- раскладка относится к товарам, рядом `/main/products/…`;
- это не поле `Company` и не настройки кассы;
- singleton без `{id}` в URL, как `/main/pos/cashier-settings/`.

### `GET /main/products/form-layout/`

Доступ: любой авторизованный сотрудник компании (кассиру нужна раскладка).

**200**

```json
{
  "hidden": ["images", "characteristics", "expiry", "debt", "adult", "promotion"],
  "updated_at": "2026-08-11T15:40:00+06:00"
}
```

Если записи ещё нет — `200` с `"hidden": []`, запись можно создать лениво.

`updated_by` отдавать не обязательно.

### `PATCH /main/products/form-layout/`

Доступ: только `owner` / `admin`. Остальным — **403**.

**Body**

```json
{
  "hidden": ["images", "characteristics", "expiry"]
}
```

| Поле | Правила |
|---|---|
| `hidden` | массив строк, обязателен. `[]` = сбросить форму к полной. `null` не принимать |
| неизвестный id | отбросить, не ошибка |
| не массив | `400` |

**200** — тот же объект, что GET (уже сохранённый, нормализованный).

Последний PATCH побеждает (без merge). Этого достаточно: настраивает обычно один человек.

## Поведение фронта (уже сделано)

1. На маунте читает `localStorage` (`market_product_form_layout_{companyId}`) — форма открывается сразу.
2. Параллельно бьёт в `GET /main/products/form-layout/`.
3. Успех → подменяет кэш и UI. `404`/`405`/`501` → остаётся кэш устройства, без тоста.
4. Owner/admin: «Настроить форму» → минус на полях → «Добавить поле» / «Готово».
5. Каждое изменение и «Готово» делают `PATCH`. Успех пишется в `localStorage`. Ошибка PATCH (кроме missing endpoint) — тост, локальный кэш не откатывается.
6. Кассир кнопку настройки не видит, только применяет раскладку с GET.

## Тест-план для бэка

- [ ] `GET` без записи → `{ "hidden": [] }`
- [ ] `GET` кассиру той же компании → 200, те же `hidden`
- [ ] `PATCH` от owner → 200, повторный `GET` с другого токена/устройства совпадает
- [ ] `PATCH` от кассира → 403, данные не меняются
- [ ] `PATCH { "hidden": ["images", "ghost", "images"] }` → сохраняется `["images"]`
- [ ] `PATCH { "hidden": [] }` сбрасывает раскладку
- [ ] сотрудник другой компании не видит чужие `hidden` (изоляция по `request.user.company`)
- [ ] без токена → 401
