# Персональные UI-настройки пользователя (сайдбар, тема, кнопка кассы)

**Экраны фронта:** `/crm/set` → вкладка **«Интерфейс»** (`src/pages/settings/ui/Settings/tabs/InterfaceTab.tsx`), применяются глобально во всём layout (`src/widgets/layout/ui/Layout.tsx`, `src/widgets/header/ui/Header.tsx`, `src/shared/theme/ThemeModeProvider.tsx`).

**Новый эндпоинт (требуется реализовать):**
- `GET /users/ui-preferences/` — прочитать персональные настройки текущего пользователя
- `PATCH /users/ui-preferences/` — частично обновить (только владелец аккаунта, сам себе)

**Фронт-клиент:** `src/shared/api/uiPreferences.ts`, синк-слой `src/shared/lib/uiPreferences.ts`
**Статус:** фронт готов и задеплоен «мягко» — пока эндпоинта нет, `GET`/`PATCH` падают тихо (перехватываются, ловятся в `catch`), приложение продолжает работать как раньше — целиком на `localStorage` этого браузера. После реализации бэка синхронизация между устройствами включится автоматически, без релиза фронта.

---

## 1. Задача

Сейчас 4 настройки интерфейса живут только в `localStorage` браузера:

| Настройка | Что делает | localStorage-ключ (сохраняется как есть, для обратной совместимости) |
|---|---|---|
| Автозакрытие сайдбара | Сайдбар закрывается сам при переходе на другую страницу | `sidebarAutoClose` |
| Кнопка «Касса» в шапке — режим | `true` — кнопка скачивает desktop-версию кассы (последний релиз с GitHub); `false` — открывает `/crm/market/cashier` (веб-версия), как раньше | `cashierDesktopButtonEnabled` |
| Тема | Светлая / тёмная | `mui-theme-mode` |
| Стиль тёмной темы | «Мягкая» / «Классическая» (только пока `mui-theme-mode=dark`) | `nur-dark-palette` |

**Проблема:** если пользователь садится за другой компьютер, открывает CRM в другом браузере или просто чистит данные сайта — все 4 настройки сбрасываются на дефолт. Это не критично для бизнеса (не деньги, не данные о продажах), но раздражает: приходится каждый раз заново выключать автозакрытие сайдбара или переключать тёмную тему.

**Решение:** персональные настройки **пользователя** (не компании — у каждого сотрудника свои), хранятся на бэке, подтягиваются при логине/обновлении профиля. `localStorage` остаётся как **мгновенный локальный кэш** (чтобы не было мигания интерфейса, пока идёт сетевой запрос) — источник правды теперь бэк.

---

## 2. Модель данных

Одна запись на пользователя (singleton, как `MarketCashierSettings` на компанию — см. [kassa/cashier-settings.md](./kassa/cashier-settings.md), только здесь FK на `User`, не на `Company`). Предлагаемая модель `UserUiPreferences`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | uuid | PK |
| `user` | FK → User, `unique=True` | Владелец настроек |
| `sidebar_auto_close` | `BooleanField(default=False)` | Автозакрытие сайдбара |
| `cashier_desktop_download` | `BooleanField(default=True)` | `true` — кнопка «Касса» скачивает desktop-приложение; `false` — открывает веб-кассу |
| `theme_mode` | `CharField(choices=["light","dark"], default="light")` | Тема интерфейса |
| `theme_dark_palette` | `CharField(choices=["soft","classic"], default="soft")` | Стиль тёмной темы |
| `updated_at` | datetime | Авто |

Запись создаётся лениво: при первом `GET`/`PATCH` — `get_or_create(user=request.user)`. Значения по умолчанию должны совпадать с дефолтами фронта (см. таблицу в §1), иначе у новых пользователей после первого же `GET` слетит текущее поведение (например, `cashier_desktop_download` **обязательно** `true` по умолчанию — иначе кнопка «Касса», которая раньше вела на веб-версию, у всех молча переключится в другой режим).

## 3. Контракт API

### 3.1 `GET /users/ui-preferences/`

Доступ: любой авторизованный пользователь, только свои настройки (по токену, без параметров).

**Ответ 200:**

```json
{
  "sidebar_auto_close": false,
  "cashier_desktop_download": true,
  "theme_mode": "light",
  "theme_dark_palette": "soft"
}
```

Когда для пользователя ещё нет записи — отдать дефолты из §2 (без ошибки).

### 3.2 `PATCH /users/ui-preferences/`

Доступ: сам пользователь, только свои настройки.

**Запрос — фронт отправляет только изменённое поле (partial update):**

```json
{ "sidebar_auto_close": true }
```

```json
{ "theme_mode": "dark" }
```

**Валидация:**

| Поле | Правило | Ошибка |
|---|---|---|
| `sidebar_auto_close`, `cashier_desktop_download` | `bool` | `400 {"sidebar_auto_close": ["Must be a valid boolean."]}` |
| `theme_mode` | `"light"` \| `"dark"` | `400 {"theme_mode": ["Допустимы light или dark"]}` |
| `theme_dark_palette` | `"soft"` \| `"classic"` | `400 {"theme_dark_palette": ["Допустимы soft или classic"]}` |

**Ответ 200** — тот же объект, что и в `GET`, целиком (фронт не использует ответ для UI, но пусть будет консистентно с остальными PATCH-эндпоинтами в проекте).

Фронт шлёт `PATCH` **при каждом переключении тумблера/темы**, не по кнопке «Сохранить» (см. §4) — то есть запросов может быть много и часто по одному полю. Эндпоинт должен быть дешёвым (`get_or_create` + `update` одного поля), без побочных эффектов.

---

## 4. Поведение фронта (что уже сделано)

1. **Первая отрисовка** — всегда мгновенно из `localStorage` (без сети), чтобы не мигало.
2. **Синхронизация с бэка** — при `getProfile` (вызывается при логине и на старте сессии, `src/entities/user/model/userSlice.ts`) фронт **дополнительно и не блокируя** запрашивает `GET /users/ui-preferences/`. Если бэк ответил — перезаписывает соответствующие ключи в `localStorage` и рассылает событие `ui-preferences-synced` (слушают `ThemeModeProvider`, `Layout`, вкладка «Интерфейс» — подхватывают новое значение на лету, даже если страница уже открыта).
3. **Сохранение** — любое изменение тумблера/темы сразу пишется в `localStorage` (как раньше) **и** отправляется на бэк через `PATCH` (fire-and-forget: если запрос упал — ошибка молча игнорируется, значение уже применено локально).
4. **Бэка ещё нет** — `GET`/`PATCH` ловятся в `catch`, ничего не падает, всё работает как до этой доработки (чисто на `localStorage`, без синка между устройствами).
5. Код: `src/shared/api/uiPreferences.ts` (HTTP), `src/shared/lib/uiPreferences.ts` (localStorage ↔ бэк мост + событие `ui-preferences-synced`).

## 5. Чек-лист для бэкенда

- [ ] Модель `UserUiPreferences` (или аналог), `get_or_create` по текущему пользователю, дефолты как в §2 (важно: `cashier_desktop_download` по умолчанию `true`)
- [ ] `GET /users/ui-preferences/` — свои настройки, дефолты если записи ещё нет
- [ ] `PATCH /users/ui-preferences/` — partial update, валидация из §3.2
- [ ] Убедиться, что эндпоинт дешёвый — фронт дёргает его на каждое переключение тумблера, не пачками
