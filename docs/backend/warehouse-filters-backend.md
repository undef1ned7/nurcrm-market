# Склад маркета (/crm/sklad) — фильтрация: вопросы бэкенду

**Эндпоинт:** `GET /main/products/list/` (он же `GET /api/main/products/list/`)
**Экран:** `/crm/sklad` (список товаров склада) + модалка «Фильтры».

> **СТАТУС: отвечено бэкендом.** Ниже — оригинальные вопросы; ответы вписаны курсивом/в блоках «BE:». Итог по фронту — в разделе 0.

---

## 0. Итог и что поправлено на фронте

**Работают все параметры**, кроме `sale_unit` (на бэке нет — фильтруется на клиенте, ок).

Правки фронта после ответа:

- Включены обратно в модалку «Фильтры»: **Остаток** (`stock_*`) и **Изменения товара** (`changes_*`) — бэк подтвердил поддержку.
- «Изменения товара»: условия приведены к `lt`/`gt` («изменён менее / более N дней назад») — раньше слался нераспознаваемый `changes_condition`.
- В `marketWarehouseFilters.ts` зафиксирован подтверждённый контракт (комментарий-шапка).

**Замечания (не блокеры):**

- `price_type=cost` и `price_type=purchase` — на бэке это **одно поле** `purchase_price`. Пункты «Себестоимость» и «Цена закупки» в UI ведут себя одинаково. Оставили оба; при желании — убрать «Себестоимость».
- `search` не ищет по `article` / `code` / `plu` / `brand` / `category`. Если нужно — отдельная задача бэку.
- Поля товара в ответе: `cost` → **`purchase_price`**, `min_stock` → **`minimum_quantity`**, `category`/`brand` — **строки** (`.name`), `suppliers` — массив `[{id, full_name}]`. Проверить потребителей на складе, если где-то читается старое имя.
- `ordering` поддержан (`created_at` | `updated_at` | `price`, префикс `-`), но UI сортировки на складе пока нет.

## 3. Общие вопросы

1. **Комбинирование фильтров** — при передаче нескольких параметров одновременно логика **AND** (все условия сразу)? Есть ли параметры, которые нельзя сочетать?
2. **`preset` + ручные фильтры** одновременно — что происходит? preset перекрывает или складывается по AND?
3. **Сортировка** — поддерживается ли `ordering` (или другой параметр)? По каким полям можно сортировать (название, цена, остаток, дата)?
4. **`page_size`** — можно ли передавать с фронта? Текущий дефолт?
5. **Неизвестные / неподдерживаемые параметры** — бэкенд их молча игнорирует или отдаёт 400? (важно: если игнорирует — пользователь думает, что фильтр применился)
6. **`count` в ответе** — это总 число с учётом фильтров или без?
7. Формат ответа списка — `{ count, next, previous, results }` (DRF пагинация) или иначе?
8. Все ли поля, по которым фильтруем, присутствуют в объекте товара в ответе (`discount_percent`, `expiration_date`, `min_stock`, `quantity`, `cost`, ...)? Перечислите, каких нет.
