# 3. Два товара с одним штрихкодом

**Приоритет:** средний
**Затрагивает:** создание и редактирование товара (`POST/PATCH /main/products/…`), поиск по штрихкоду

---

## 3.1. Что нашли

При проверке поиска в «Калькуляции» `GET /main/products/list/?search=4011100091108` в компании `4b759359-2239-4e2a-a07e-f0e42a4dd19d` вернул **два разных товара** с одинаковым штрихкодом:

| id | code | name | barcode | quantity | status |
|---|---|---|---|---|---|
| `532685d6-15a1-4651-a8cc-d42f79b8d960` | 0138 | Батончик Mars 50г | 4011100091108 | 48 | `null` |
| `3c9d4d25-593c-47bd-a389-053928365228` | 0143 | Батончик Mars 50г | 4011100091108 | 0 | `accepted` |

## 3.2. Чем это плохо

- **Касса и сканер.** Какой из двух товаров пробьётся по скану — неочевидно. Остаток уходит в минус у одного, пока у другого 48 шт.
- **Калькулятор.** При скане со сканером фронт выбирает товар сам, только если совпадение одно. С дублем пользователь видит два одинаковых «Батончик Mars 50г» и должен угадать.
- **Отчёты.** Продажи одного товара разбиты на две карточки.

## 3.3. Вопросы бэкенду

1. Это допустимо по модели (например, второй товар — принятый по накладной, `status = accepted`) или дубль по ошибке?
2. Если не должно быть — запретить при сохранении: штрихкод (включая `alternate_barcodes`, см. [`../alternate-barcodes.md`](../alternate-barcodes.md)) уникален в пределах компании (или филиала). Ответ `400` с понятным текстом: «Штрихкод уже есть у товара „…“ (код 0138)».
3. Для уже существующих дублей — отдать список, чтобы владелец мог объединить или исправить:

   ```
   GET /main/products/duplicate-barcodes/
   → [{ "barcode": "4011100091108", "products": [{ "id": "…", "code": "0138", "name": "…", "quantity": "48.000" }, …] }]
   ```

   Фронт может показать это в «Проверке цен» отдельным фильтром «Дубли штрихкода».

## 3.4. Как проверим

1. Создать товар со штрихкодом, который уже есть, — `400` с текстом.
2. Добавить чужой штрихкод в `alternate_barcodes` — тоже `400`.
3. `duplicate-barcodes` на тестовой компании находит пару Mars.

---

## Ответ BE

**Ответ BE (08.10.2026).**

1. **Пара Mars — не ошибка данных.** При перемещении товара между филиалами на получателе создаётся своя карточка с тем же штрихкодом и своим остатком; статус `accepted` ставится, если у исходной пусто. Внутри одного филиала или основного склада дубль запрещён и раньше — проверкой в коде и ограничением в базе.
2. **Текст ошибки** при дубле называет товар: «Штрихкод … уже есть у товара „Батончик Mars 50г“ (код 0138)». Так же для дополнительных штрихкодов. Фронт показывает текст сервера как есть (`validateResErrors`), правки не нужны.
3. **Список дублей:** отдельного эндпоинта нет. Существующий `barcode-duplicates/` получил поля `code`, `status`, название филиала и `same_scope`; путь `duplicate-barcodes/` из этого документа ведёт туда же. `same_scope: true` — настоящий дубль в одном складе, его нужно объединить; `false` — нормальные копии по филиалам.

**Фронт:** фильтр «Дубли штрихкода» в «Проверке цен» пока не сделан — ждёт решения, показывать ли только `same_scope: true`.

**Предложение BE по кассе (не сделано):** скан товара, перемещённого в филиал, сейчас даёт кассиру «неоднозначный штрихкод» и выбор карточки вручную. Касса филиала могла бы сама брать свою карточку — нужно решение, на чьей стороне.
