# 2. Признак «каталог изменился»

**Приоритет:** средний
**Затрагивает:** `GET /main/products/list/` (и новый `GET /main/products/price-check/` из задачи 1)

---

## 2.1. Как сейчас

«Проверка цен» обновляется сама каждые 2 минуты, пока вкладка открыта: заново скачивает весь каталог, даже если за это время ничего не поменялось. Узнать «есть ли изменения» без полной выгрузки фронту нечем.

Ответ `/main/products/list/` сейчас идёт без `ETag` и `Last-Modified`.

## 2.2. Что нужно — один из вариантов

### Вариант А (предпочтительно): `ETag` + `304`

- На `GET /main/products/price-check/` (и/или `/main/products/list/`) отдавать заголовок `ETag`, зависящий от версии каталога компании.
- Если фронт прислал `If-None-Match` с тем же значением — ответ `304 Not Modified` без тела.
- Версию можно хранить как счётчик или `max(updated_at)` по товарам компании; меняется при любом изменении товара, остатка, цены, закупки.

Пример: `/main/public/companies/{slug}/showcase/design/` уже так делает (`ETag: "v3-…"`), можно по образцу.

### Вариант Б: лёгкий эндпоинт версии

```
GET /main/products/catalog-version/
→ { "version": "2026-10-06T10:15:00.123456+06:00", "products_total": 20000 }
```

Фронт раз в 2 минуты спрашивает версию и перезагружает данные, только если она поменялась.

### Вариант В: событие по WebSocket

Если удобнее — событие `market.catalog.changed` в существующий канал уведомлений (см. `kassa/realtime-notifications-backend.md`). Тогда опрос раз в 2 минуты не нужен вовсе.

## 2.3. Что сделает фронт после

- Автообновление «Проверки цен» станет почти бесплатным: `304` или сравнение версии.
- То же можно применить к «Сводке» и ABC.

## 2.4. Как проверим

1. Два обновления подряд без изменений — второй ответ `304` (или та же `version`).
2. Поменяли цену одного товара — следующий запрос отдаёт новые данные.
3. Продажа/приход меняет остаток — версия меняется.

## Ответ BE

**Готово (BE, 08.10.2026): варианты А и Б.**

- А: `price-check/` отдаёт `ETag`; тот же `If-None-Match` → `304` без тела, ~40 мс.
- Б: `GET /main/products/catalog-version/` — лёгкая версия каталога, ~30 мс. Для списка товаров, «Сводки» и ABC.
- Версия считается из самих товаров: количество, время последнего изменения, контрольные суммы остатков, цен и закупок. Меняется при правке, продаже, приходе, удалении и при переносе остатка между товарами с той же общей суммой. Отдельных счётчиков и сброса кэша нет — рассинхрона быть не может.

**Фронт (08.10.2026)** — `src/entities/product/api/catalogVersion.ts`:

- «Проверка цен»: автообновление по версии, см. задачу 1.
- «Сводка», блок «Заканчивается на складе»: автообновление раз в 2 минуты перекачивает остатки, только если версия изменилась. Кнопка «Обновить» грузит всегда.
- ABC, срез «Склад»: каталог кэшируется по версии — повторный расчёт и смена периода не качают его заново.
- Список товаров склада: кэш страницы (5 минут) помнит версию; при возврате на страницу с той же версией список не запрашивается.
- Версию фронт берёт **до** загрузки данных: если каталог поменяется посреди загрузки, следующая проверка увидит новую версию.
- Ответ читается как `{ "version": … }` (или голая строка). Если эндпоинта нет (`404`), фронт больше не спрашивает до перезагрузки и грузит данные, как раньше.
