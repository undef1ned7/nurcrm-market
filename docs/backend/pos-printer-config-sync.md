# POS: синхронизация ESC/POS-конфига принтера (low priority)

**Статус:** 💡 Nice-to-have. Сейчас настройки только в `localStorage` браузера кассы (`escpos_*`). Фронт уже умеет **экспорт/импорт JSON** на `/crm/pos-print-settings`.

---

## 1. Проблема

Конфиг ширины бумаги, code page, VID/PID принтера и денежного ящика:

- теряется при смене ПК / профиля браузера / очистке сайта;
- нельзя удалённо посмотреть, что выставлено на кассе;
- поддержка просит кассира вручную пересылать JSON.

## 2. Идея API (черновик)

Опциональное per-device (или per-branch workstation) хранилище.

### Модель

```json
{
  "device_key": "cashier-front-1",
  "settings": {
    "escpos_dpl": "384",
    "escpos_cpl": "42",
    "escpos_font": "B",
    "escpos_line": "22",
    "escpos_cp": "17",
    "escpos_drawer_enabled": "1",
    "escpos_drawer_when": "after",
    "escpos_drawer_cmd": "27, 112, 0, 25, 250"
  },
  "updated_at": "2026-08-24T12:00:00+06:00"
}
```

`escpos_vid` / `escpos_pid` / `escpos_serial` — **опционально** и осторожно: привязка к железу на другой машине может мешать.

### Эндпоинты (предложение)

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/main/pos/printer-settings/?device_key=` | прочитать конфиг устройства |
| PUT/PATCH | `/main/pos/printer-settings/` | сохранить `{ device_key, settings }` |

Авторизация: сотрудник с доступом к кассе / настройкам компании. Не секреты оплаты — только local printer prefs.

### `device_key`

Генерирует фронт один раз (`localStorage` / fingerprint), чтобы несколько касс в одном филиале не затирали друг друга.

## 3. Поведение фронта (когда появится API)

1. При открытии `/crm/pos-print-settings` — опционально подтянуть remote и предложить «Применить с сервера».
2. После «Сохранить» — писать и в `localStorage`, и на API (best-effort).
3. Экспорт/импорт JSON оставить как offline-фолбэк.

## 4. Приоритет

**Low.** Не блокирует продажи. Сначала — флаги цены и eKassa `item_id` (см. соседние docs). Этот документ — чтобы не потерять идею.
