# 2. «Последние продажи»

**Приоритет:** средний
**Эндпоинт:** `GET /main/pos/sales/`

---

## 2.1. Как сейчас запрашивает фронт

```
GET /main/pos/sales/?page_size=24&ordering=-created_at
```

- `ordering=-created_at` — то же, что в окне чеков кассы (`ReceiptsModal`). До стресс-теста сортировки не было, и «последние» зависели от порядка по умолчанию.
- Берётся с запасом (24), потому что открытые корзины кассира (`status = new`) фронт отбрасывает сам: это ещё не продажа. Показываются первые 8 оставшихся.

## 2.2. Что нужно

### А. Отсекать открытые корзины на сервере

Если корзин «в работе» больше 16 (несколько касс), в «Последних продажах» окажется меньше 8 строк. Нужен один из параметров:

- `status__in=paid,debt,canceled` (список), или
- `exclude_status=new`, или
- `only_finished=true`.

Подтвердите имя — фронт переключится на него и вернёт `page_size=8`.

### Б. Сортировка по времени оплаты

Для «последних продаж» правильнее время оплаты: чек могли открыть утром, а оплатить вечером. Поддерживается ли `ordering=-paid_at`? Для чеков без `paid_at` (продажа в долг, см. `../analytics-market-sales-fixes-backend.md` §4) — `Coalesce(paid_at, created_at)`.

### В. Название товара в строке списка

Колонка «Товар» берёт `items[0].name`. Окно чеков в кассе загружает товары каждого чека отдельным запросом, значит, в списке `items` нет, и колонка почти всегда «—».

Нужно в каждой строке списка (без полной загрузки позиций):

```json
{
  "id": "…",
  "items_preview": "Батончик Mars 50г",
  "items_count": 3
}
```

Фронт покажет «Батончик Mars 50г и ещё 2».

## 2.3. Как проверим

1. Открыты 20 корзин и есть 8 оплаченных чеков — в списке 8 оплаченных, ни одной корзины.
2. Чек открыт в 09:00, оплачен в 18:00 — стоит выше чека, открытого и оплаченного в 12:00.
3. У каждой строки есть название первого товара и количество позиций.
