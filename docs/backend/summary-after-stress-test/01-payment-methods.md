# 1. «Способы оплаты»: смешанная оплата и названия методов

**Приоритет:** высокий
**Эндпоинт:** `GET /main/analytics/market/?tab=sales` → `charts.payment_methods`

---

## 1.1. Возможный двойной счёт

В [`../analytics-market-sales-calculation.md`](../analytics-market-sales-calculation.md) сказано:

> `charts.payment_methods` — группировка по `payment_method`: `{method, count, total}`. Для `mixed` добавлены `cash` и `card` из строк `SalePayment`.

Непонятно, остаётся ли при этом в ответе строка `mixed`. Если да, продажа на 1000 сом (600 наличными + 400 картой) приходит так:

```json
[
  { "method": "mixed", "count": 1, "total": "1000.00" },
  { "method": "cash",  "count": 1, "total": "600.00" },
  { "method": "card",  "count": 1, "total": "400.00" }
]
```

Сумма строк — 2000 при выручке 1000. Раньше «Сводка» показывала «Наличные 600», «Безналичные 400» и «Смешанная 1000» как три отдельные суммы.

**Что сделал фронт (временно):** если сумма всех строк больше выручки, а без `mixed` совпадает с ней — строка «Смешанная» показывается серым как «в том числе смешанная оплата (уже учтена выше)». Это эвристика, нужен однозначный контракт.

### Вопросы

1. Приходит ли `mixed` вместе с разложенными `cash`/`card`?
2. Что должно быть в ответе? Предлагаем один из вариантов:
   - **А (лучше):** строки только по фактическим деньгам (`cash`, `card`, `transfer`, `debt`…), без `mixed`; отдельно — `cards.mixed_total` и `cards.mixed_count` для справки;
   - **Б:** строка `mixed` есть, но с флагом `"included_in_other": true`.
3. Сумма `total` по строкам должна совпадать с `cards.revenue`. С учётом возвратов — по тому же правилу, что в [`../analytics-market-sales-fixes-backend.md`](../analytics-market-sales-fixes-backend.md) §3.

## 1.2. Список значений `method`

Фронт раскладывает метод по строкам по подстрокам названия (`paymentKind` в `summaryData.ts`):

| Строка «Сводки» | Что сейчас распознаётся |
|---|---|
| Наличные | `cash`, «налич» |
| Безналичные | `card`, `transfer`, `bank`, `qr`, `pos`, `terminal`, `mbank`, `elsom`, `odengi`, `optima`, `megapay`, `cashless`, `noncash`, «карт», «перевод», «безнал», «мбанк», «элсом», «О!Деньги»… |
| В долг | `debt`, «долг» |
| Смешанная | `mixed`, `split`, «смеш» |
| Другое | всё остальное |

До стресс-теста «Карта», «Перевод», «Элсом», «О!Деньги», «Мбанк» уходили в «Другое», а `cashless` — в «Наличные».

### Вопрос

Пришлите **полный список** значений `payment_method` у продажи (и `method` у `SalePayment`), которые сейчас бывают в базе, с русской подписью. Тогда фронт заменит угадывание по подстрокам точной таблицей.

## 1.3. Старый формат «только количество»

Если строка пришла без суммы (`{ "method": "cash", "count": 7 }`), раньше «Сводка» показывала «7 сом». Сейчас такие строки не показываются. Подтвердите, что `total` (или `value`) приходит всегда.
