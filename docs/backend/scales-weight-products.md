**Полная документация (фронт + сценарии + troubleshooting):** [`docs/market/scales-and-plu.md`](../market/scales-and-plu.md)

**Страница фронта:** `/crm/scales` → `src/features/warehouse-ops/ui/ScalesPage.tsx`  
**Статус:** ✅ Реализовано с обеих сторон (июль–август 2026)

---

## 1. Контекст

Страница «Весы» и касса работают с **весовыми товарами** — позициями, у которых:

- `is_weight = true`, **или**
- `scale_type = "weight"`.

У каждого весового товара может быть поле **`plu`** (число) — код в памяти торговых весов.

---

## 2. Товары: фильтр весовых в списке

### 2.1. Эндпоинт

```
GET /main/products/list/?is_weight=true
```

| Параметр | Тип | Описание |
|---|---|---|
| `is_weight` | bool (`true`/`false`) | Вернуть только товары, где `is_weight = true` **или** `scale_type = "weight"` (при `false` — все остальные) |

Правила:

1. Фильтр комбинируется с существующими параметрами (`page`, `search`, `kind` и т.д.).
2. `count` в ответе — количество товаров **после** фильтра (фронт показывает как «Весовых товаров для выгрузки»).
3. Отсутствие параметра — прежнее поведение (весь каталог).
4. Невалидное значение (`is_weight=abc`) — HTTP 400 с `detail`.

### 2.2. Поля товара (создание / обновление)

| Поле | Тип | Правила |
|------|-----|---------|
| `is_weight` | `boolean` | `true` для весового товара и дробной услуги |
| `scale_type` | `"weight"` \| `"piece"` \| `null` | Legacy-дублирование; синхронизировать с `is_weight` |
| `plu` | `number` \| `null` | Только для весовых; уникальность в рамках компании желательна |

## 3. Отправка на весы Штрих-М

```
POST /users/scales/send-products/
```

```json
{
  "plu_start": 1,
  "product_ids": ["uuid-1", "uuid-2"]
}
```

| Поле | Описание |
|------|----------|
| `plu_start` | Стартовый PLU при автоназначении на весах |
| `product_ids` | Список id товаров для выгрузки |

Требования:

1. При переданном `product_ids` на весы уходят **только** эти товары — без фолбэка на весь каталог.
2. Пустой `product_ids: []` — HTTP 400 с `detail` («нет товаров для отправки»).
3. Несуществующий id — не выгружать весь каталог; вернуть ошибку или пропустить с явным отчётом.

**Thunk фронта:** `sendProductsToScales` → `src/entities/user/model/userCreators.ts`

## 4. Экспорт для весов Rongta

```
GET /main/products/scale-export/?format=txp&translit=1
```

| Параметр | Значения | Описание |
|----------|----------|----------|
| `format` | `txp`, `xls` | Формат файла (TXP — основной для Rongta RLS) |
| `translit` | `0`, `1` | Транслитерация названий в латиницу |

Ответ: файл (`Content-Disposition: attachment`).  
Опциональный заголовок: `X-Scale-Products-Count` — число товаров в выгрузке.

Правила:

1. В выгрузку попадают только весовые товары (`is_weight` / `scale_type = weight`).
2. Товарам без `plu` — автоназначение PLU при экспорте.
3. Ошибки (нет весовых) — HTTP 400, тело с `detail` (фронт читает из blob).

## 6. Настройки чтения штрихкода весов (компания)

```
GET  /users/settings/company/
PATCH /users/settings/company/
```

| Поле | Значения | Назначение |
|------|----------|------------|
| `scale_barcode_layout` | `plu`, `code` | Как извлекать идентификатор товара из штрихкода этикетки |
| `scale_barcode_mode` | `auto`, `weight`, `amount` | Как интерпретировать значение (граммы / сомы / авто по префиксу) |

Применяются при `POST /main/pos/sales/{id}/scan/` на бэкенде.

### 6.1. Раскладки

**По PLU** (`plu`): `префикс(2) + PLU(5) + значение(5) + контрольная(1)`

**По коду** (`code`): `префикс(2) + Код(6) + вес(4) + контрольная(1)`

### 6.2. Режимы значения

| Режим | Поведение |
|-------|-----------|
| `auto` | Префикс 20 → вес (граммы), 25 → сумма (сомы × 100) |
| `weight` | Значение всегда в граммах → qty = value / 1000 кг |
| `amount` | Значение в сомах × 100 → пересчёт qty по цене товара |

### 6.3. Пример

Этикетка: `2100100001452`, PLU товара = 1, вес = 0.145 кг

| layout | Результат |
|--------|-----------|
| `plu` | PLU = 100 — **не совпадает** |
| `code` | Код 001000 → PLU 1, вес 145 г = 0.145 кг — **верно** |

Для Rongta RLS (префикс 21): обычно `layout=code`, `mode=weight`.

## 7. POS: сканирование штрихкода весов

```
POST /main/pos/sales/{sale_id}/scan/
```

```json
{ "barcode": "2100100001452" }
```

Бэкенд:

1. Определяет, является ли штрихкод весовым (по префиксу и длине).
2. Разбирает по `scale_barcode_layout` и `scale_barcode_mode` компании.
3. Находит товар по `plu` (или по внутреннему коду при layout `code`).
4. Добавляет в корзину с `quantity` = извлечённый вес (кг) или рассчитанным из суммы.

Фронт передаёт штрихкод без предобработки (`sendBarCode` thunk).

## 9. Чек-лист приёмки

Данные: каталог из 5 товаров — 2 весовых (`is_weight=true` или `scale_type="weight"`), 3 штучных.

| # | Запрос / действие | Ожидание |
|---|---|---|
| 1 | `GET /main/products/list/?is_weight=true` | `count=2`, в `results` только весовые |
| 2 | `GET /main/products/list/?is_weight=true&search=<имя>` | фильтры комбинируются |
| 3 | `GET /main/products/list/` (без параметра) | `count=5`, поведение не изменилось |
| 4 | `GET /main/products/list/?is_weight=abc` | HTTP 400 с `detail` |
| 5 | `POST /users/scales/send-products/` с 2 весовыми id | на весы уходят ровно 2 товара |
| 6 | `POST /users/scales/send-products/` с `product_ids: []` | HTTP 400 |
| 7 | `GET /main/products/scale-export/?format=txp` | файл только с весовыми; PLU автоназначение |
| 8 | `PATCH` company `scale_barcode_layout=code` + scan этикеты Rongta | товар найден, вес верный |
| 9 | Создать весовой товар с `plu: 5`, scan этикеты с PLU 5 | позиция в чеке с верным весом |
| 10 | PLU в этикетке ≠ PLU в системе | HTTP 4xx / сообщение «товар не найден» |
