# Исправление: `postCashflowIfNeeded` — убрать или задокументировать как мёртвый код

**Баг:** [sale-flow-bugs.md, пункт 6](../sale-flow-bugs.md#6--postcashflowifneeded-фактически-мёртв)
**Нужен бэк:** нет
**Приоритет:** 🟡 низкий — не искажает данные, но вводит в заблуждение при чтении кода

---

## 1. Контекст

Решение от 2026-09-29: **все денежные операции (cashflows) теперь создаёт бэкенд**, фронт этим не занимается. `postCashflowIfNeeded` (`src/entities/cash/lib/postCashflowIfNeeded.ts:46`) и так уже фактически не работает — она выходит без действия, если `hasExplicitCashbox(payload.cashbox)` ложно, а касса оплаты никогда не передаёт явный `cashbox`. То есть поведение уже соответствует требуемому (бэк создаёт cashflows сам), просто код выглядит так, будто он что-то делает.

## 2. Проблема с текущим состоянием

Вызовы `postCashflowIfNeeded(dispatch, {...}, {...})` разбросаны по `usePaymentPage.ts` (несколько мест — оплата, предоплата по долгу, split-платёж) и `useSellMainStartCheckout.ts`. Каждый вызов:
- выглядит как значимая часть бизнес-логики (собирает `name`, `amount`, `source_cashbox_flow_id`, `status` в зависимости от тарифа);
- на самом деле не делает ничего, кроме `return undefined` на самой первой строке (`hasExplicitCashbox` всегда `false`).

Риск: кто-то, читая код или отлаживая расхождение по кассе, потратит время на анализ этой ветки, решив, что она реально создаёт cashflow.

## 3. Вариант A (минимальный) — задокументировать

Ничего не удалять, просто явно пометить каждый вызов и саму функцию:

```ts
// postCashflowIfNeeded.ts
/**
 * @deprecated Фактически no-op в текущей конфигурации: страница оплаты
 * никогда не передаёт явный `cashbox` (маршрутизацию выбирает бэк), поэтому
 * `hasExplicitCashbox` всегда false. С 2026-09-29 все cashflows создаёт
 * бэкенд — эта функция оставлена как legacy-путь на случай отката
 * VITE_BE_CASHFLOWS, но в проде не выполняет никаких действий.
 * См. docs/sale-flow-bugs.md, пункт 6.
 */
export async function postCashflowIfNeeded(...) { ... }
```

Плюс однострочный комментарий на каждом вызове в `usePaymentPage.ts`/`useSellMainStartCheckout.ts`:
```js
// no-op в текущей конфигурации — см. postCashflowIfNeeded.ts
await postCashflowIfNeeded(dispatch, {...}, {...});
```

## 4. Вариант B (полная уборка) — удалить

Если команда уверена, что откат на фронтовый фолбэк (`VITE_BE_CASHFLOWS=false` + явный `cashbox`) больше никогда не понадобится:

1. Убрать все вызовы `postCashflowIfNeeded` из `usePaymentPage.ts` и `useSellMainStartCheckout.ts`.
2. Удалить `postCashflowIfNeeded.ts`, `hasExplicitCashbox`/`shouldPostCashflowFallback` (если больше нигде не используются — проверить `backendCashflows.ts` на другие точки использования перед удалением).
3. Проверить `addCashFlows` в `cashSlice.ts` — используется ли он где-то ещё (ручное добавление движения в UI кассы, `AddCashFlowsModal.tsx`), если да — не трогать сам thunk, удалять только вызовы из потока продажи.

**Рекомендация:** начать с варианта A (быстро, без риска), вариант B делать отдельной задачей после того, как `VITE_BE_CASHFLOWS`/бэкенд-cashflows подтверждённо стабилизируются на проде для всех компаний (не только тестовых).

## 5. Бэк

Не требуется — это чисто уборка на фронте, отражающая уже принятое решение.
