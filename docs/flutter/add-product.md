# Flutter: экран `/crm/sklad/add-product`

Документ для мобильного клиента NurCRM Market. Описывает экран **создания и редактирования товара** так, как он работает на веб-фронте (`nur-market`). Цель — повторить контракт API, валидацию, расчёты и побочные эффекты 1:1.

**Веб-экран:** `/crm/sklad/add-product` и `/crm/sklad/add-product/:id`  
**Веб-код:** `src/features/warehouse-ops/ui/AddProductPage/`  
**Архитектура веб-экрана:** [docs/market/add-product-page.md](../market/add-product-page.md)  
**Заголовок:** «Создание товара» / «Редактирование товара»  
**Валюта в UI:** COM (сом)  
**Таймзона бизнеса:** Asia/Bishkek, UTC+6

Связанные бэкенд-доки:

- [product-form-layout-backend.md](../backend/product-form-layout-backend.md) — раскладка формы
- [adult-products-backend.md](../backend/adult-products-backend.md) — флаг 18+
- [alternate-barcodes.md](../backend/alternate-barcodes.md) — доп. штрихкоды
- [scales-weight-products.md](../backend/scales-weight-products.md) — весовые товары / PLU
- [debt-installment-schedule-backend.md](../backend/kassa/debt-installment-schedule-backend.md) — сделки-долги

## 1. Общие правила API

Базовый префикс: `{host}/api`. **Не** вводить `/api/v1/`.

|                   |                                                                                     |
| ----------------- | ----------------------------------------------------------------------------------- |
| Авторизация       | `Authorization: Bearer <accessToken>`                                               |
| Content-Type JSON | `application/json`                                                                  |
| Картинки          | `multipart/form-data`                                                               |
| Ошибки            | `{ "detail": "…" }` или `{ "message": "…" }`, либо объект полей `{ "name": ["…"] }` |
| Цены / проценты   | строки, разделитель `.` (на вводе с клавиатуры принимать и `,`)                     |
| Даты              | `YYYY-MM-DD`                                                                        |
| UUID              | строка                                                                              |

Роль пользователя: `GET /users/profile/` → `role` (`owner` / `admin` / сотрудник).  
Компания: `GET /users/company/` → `id`, `subscription_plan.name` (важно для тарифа «Старт»).

## 2. Маршруты и режимы экрана

| Режим                | Как открыть                            | Что делать                                                              |
| -------------------- | -------------------------------------- | ----------------------------------------------------------------------- |
| Создание             | `GET` без id                           | Пустая форма, авто-штрихкод, авто-код товара                            |
| Редактирование       | `GET /main/products/{id}/`             | Заполнить форму, тип (товар/услуга/комплект) **нельзя сменить**         |
| Дублирование         | создание + данные исходного товара     | Как создание: очистить `barcode`, `quantity`, не копировать id картинок |
| Встроенный (закупки) | создание с предзаполненным поставщиком | После сохранения закрыть sheet, не уходить на склад                     |

На вебе:

- создание: `/crm/sklad/add-product`
- редактирование: `/crm/sklad/add-product/{id}` (с карточки `/crm/sklad/{id}`)
- дублирование: navigate на создание с `productData` исходного товара
- возврат: `/crm/sklad`, либо путь, с которого пришли (закупки)

Flutter: один экран `AddProductPage` с аргументами:

```dart
class AddProductArgs {
  final String? productId;          // null = создание
  final bool duplicate;             // true = копия без id
  final Map<String, dynamic>? duplicateSource;
  final String? prefillSupplierId;  // uuid поставщика из прихода
  final String? returnTo;           // куда вернуться
}
```

Кнопки внизу:

- «Отмена» → назад
- «Создать товар» / «Сохранить изменения» (disabled, пока идёт запрос)

После успеха: тост «Товар успешно добавлен!» / «Товар успешно обновлен!», через ~1.5 с — назад.

## 3. Структура экрана

### 3.1. Шапка

- Заголовок + подзаголовок
- «Вернуться к складу»
- **Только owner/admin:** кнопка «Настроить форму» (см. §8)

### 3.2. Вкладки (только создание, не редактирование)

1. **Ввод вручную** — полная форма (§4–§7)
2. **Сканирование** — упрощённая форма после скана штрихкода (§15)

### 3.3. Выбор типа (только создание)

Три карточки. В редактировании селектор **скрыт**, тип берётся из `kind`.

| UI       | Внутренний тип | API `kind` | Смысл                          |
| -------- | -------------- | ---------- | ------------------------------ |
| Товар    | `product`      | `product`  | Есть остаток, закупка, наценка |
| Услуга   | `service`      | `service`  | Нет остатка                    |
| Комплект | `kit`          | `bundle`   | Состоит из других товаров      |

Подписи на карточках:

- Товар: «Продукт, имеющий остаток, который необходимо восполнять»
- Услуга: «Продукт, не имеющий остатка на складе»
- Комплект: «Продукт, состоящий из нескольких других»

### 3.4. Порядок блоков формы (товар)

1. Тип
2. Основная информация (имя, код, штрихкод, доп. коды, артикул, горячая клавиша)
3. Изображения
4. Категория + бренд
5. Единица / флаги / упаковки / количество
6. Акция
7. PLU (если весовой)
8. Характеристики + описание
9. Страна
10. Цены
11. Склад (поставщик, долг, мин. остаток)
12. Срок годности
13. Настройка формы (owner/admin) + «Добавить поле»
14. Отмена / Сохранить

Для **услуги** блоки 6, 10–12 (акция, складские цены закупки, поставщик, долг, срок) не показываются. Вместо цен — только цена продажи и скидка.

Для **комплекта** вместо склада/цен товара — состав комплекта + цена комплекта.

## 4. Bootstrap при открытии

Параллельно:

| Запрос                                        | Зачем                                                                |
| --------------------------------------------- | -------------------------------------------------------------------- |
| `GET /main/clients/`                          | Поставщики: `type == "suppliers"`                                    |
| `GET /construction/cashboxes/`                | Первая касса → расход при создании                                   |
| `GET /main/products/list/?page_size=100`      | `count` для кода товара, число весовых для PLU, кандидаты в комплект |
| `GET /main/brands/?page=1&page_size=100`      | Справочник брендов                                                   |
| `GET /main/categories/?page=1&page_size=100`  | Справочник категорий                                                 |
| `GET /main/products/form-layout/`             | Раскладка формы (404/405/501 — ок, см. §8)                           |
| `GET /users/profile/` + `GET /users/company/` | Роль, тариф, `company.id`                                            |
| `GET /main/products/{id}/`                    | Только редактирование                                                |

Автозаполнение при **создании**:

1. **Штрихкод** — если пустой, сгенерировать EAN-13 (алгоритм §9.1).
2. **Код товара** — `String((count + 1)).padLeft(4, '0')` (например `0042`). Поле read-only, **на API не отправляется**.
3. **Артикул** — если пользователь его не менял, равен коду товара.
4. **PLU** — если включён «Весовой товар» / «Дробная услуга» и поле пустое: `weightProductsCount + 1`. Если флаг выключили — очистить PLU.
5. **Касса** — первая из списка.
6. **Поставщик** — если пришли из прихода с `prefillSupplierId`.

`weightProductsCount` на вебе считается по текущей странице списка (`is_weight == true`). Для Flutter лучше: `GET /main/products/list/?is_weight=true` и взять `count` (см. scales-доки). Fallback: посчитать по загруженной странице.

## 5. Загрузка товара (редактирование)

`GET /main/products/{id}/`

Маппинг `kind` → тип формы:

| `kind`    | Тип формы |
| --------- | --------- |
| `service` | услуга    |
| `bundle`  | комплект  |
| иначе     | товар     |

Цены при загрузке округлять до **3** знаков после запятой:

```
n = Number(value.replace(',', '.'))
display = (n * 1000).round() / 1000
```

Нули в хвосте дробной части убирать у количества, наценки, скидки, габаритов: `"10.500"` → `"10.5"`, `"10.000"` → `"10"`.

Поля ответа → форма:

| API                                             | Форма                                                        |
| ----------------------------------------------- | ------------------------------------------------------------ |
| `name`                                          | наименование                                                 |
| `barcode`                                       | основной штрихкод                                            |
| `alternate_barcodes[]`                          | доп. штрихкоды, join через `\n`                              |
| `brand_name`                                    | бренд (строка, не id)                                        |
| `category_name`                                 | категория (строка, не id)                                    |
| `price`                                         | цена продажи                                                 |
| `wholesale_price`                               | оптовая                                                      |
| `quantity`                                      | количество                                                   |
| `client`                                        | uuid поставщика                                              |
| `purchase_price`                                | цена закупки                                                 |
| `code`                                          | код (read-only)                                              |
| `article`                                       | артикул                                                      |
| `hotkey_group`                                  | `F1`…`F12` или пусто                                         |
| `unit`                                          | единица, default `"шт"`                                      |
| `is_weight`                                     | весовой товар **или** дробная услуга                         |
| `is_adult` / `is_18_plus`                       | товар 18+ (см. §14)                                          |
| `plu`                                           | PLU, строкой                                                 |
| `characteristics.height_cm`                     | высота                                                       |
| `characteristics.width_cm`                      | ширина                                                       |
| `characteristics.depth_cm`                      | глубина                                                      |
| `characteristics.factual_weight_kg`             | фактический вес                                              |
| `characteristics.description` или `description` | описание                                                     |
| `country`                                       | страна (русское имя, напр. `"Кыргызстан"`)                   |
| `markup_percent`                                | наценка %                                                    |
| `discount_percent`                              | скидка %                                                     |
| `expiration_date`                               | срок годности                                                |
| `packages[]`                                    | упаковки; если массив не пуст — включить «Поштучная продажа» |
| `stock`                                         | акционный товар                                              |
| `promotion_rules[]`                             | ступени акции                                                |
| `images[]`                                      | `{ id, alt, is_primary, image_url \| image }`                |

Комплект: состав из `packages` на вебе при редактировании **пока не восстанавливается** (остаётся пустым). Flutter может сделать лучше: если в `packages` есть товары с id — показать их в составе. Если только имена — оставить как упаковки.

Минимальный остаток (`minStock`) в API **нет**. Поле в UI есть, на сервер **не слать**.

## 6. Каталог полей

`*` — обязательное на клиенте. Скрываемые блоки помечены id раскладки (`hidden[]`, §8).

Нельзя прятать: **наименование, количество, цена закупки, цена продажи, тип товара, кнопки сохранить/отмена**.

### 6.1. Основное

| UI                  | id раскладки        | Обязательно | API                            | Примечание                                                           |
| ------------------- | ------------------- | ----------- | ------------------------------ | -------------------------------------------------------------------- |
| Наименование        | —                   | да          | `name`                         | trim                                                                 |
| Код товара / услуги | `code`              | нет         | —                              | read-only, не отправлять                                             |
| Штрих-код           | `barcode`           | да          | `barcode`                      | кнопка «Сгенерировать»; пустой → `null` только если обойти валидацию |
| Доп. штрихкоды      | `alternateBarcodes` | нет         | `alternate_barcodes: string[]` | по одному в строке, или через `,` / `;`                              |
| Артикул             | `article`           | нет         | `article`                      | default = код товара                                                 |
| Горячая клавиша     | `hotkey`            | нет         | `hotkey_group`                 | `""` → `null`; иначе `F1`…`F12` uppercase                            |
| Изображения         | `images`            | нет         | отдельный multipart            | см. §12                                                              |

Доп. штрихкоды перед отправкой:

1. Разбить по `\n`, `\r`, `,`, `;`
2. Убрать пробелы внутри кода
3. Отбросить пустые
4. Отбросить совпадение с основным `barcode`
5. Схлопнуть дубли (case-insensitive)

### 6.2. Классификация

| UI        | id         | API             | Примечание                                           |
| --------- | ---------- | --------------- | ---------------------------------------------------- |
| Категория | `category` | `category_name` | строка имени, не uuid. Поиск + «+ Создать категорию» |
| Бренд     | `brand`    | `brand_name`    | строка имени. Поиск + «+ Создать бренд»              |

Справочники:

```
GET  /main/categories/?search=&page=1&page_size=100
POST /main/categories/   { "name": "Напитки" }

GET  /main/brands/?search=&page=1&page_size=100
POST /main/brands/       { "name": "Coca-Cola" }
```

Поиск с debounce ~350 мс. Пагинация: `next` / `count`, догрузка `append`.  
Перед созданием: trim, сравнение имён case-insensitive — если уже есть, ошибка «уже существует», кнопку «Создать» disabled.  
После создания — сразу выбрать новое имя в селекте.

### 6.3. Единицы и флаги

| UI                | id          | Для кого                             | API                                         |
| ----------------- | ----------- | ------------------------------------ | ------------------------------------------- |
| Единица измерения | `unit`      | все                                  | `unit`, default `"шт"`                      |
| Поштучная продажа | `pieceSale` | только товар                         | если выкл. → `packages_input: []`           |
| Весовой товар     | `weight`    | товар                                | `is_weight`                                 |
| Дробная услуга    | `weight`    | услуга                               | `is_weight`                                 |
| Товар 18+         | `adult`     | только товар                         | `is_adult` (услуга/комплект всегда `false`) |
| Упаковки          | `packaging` | товар при поштучной; комплект всегда | `packages_input`                            |
| Количество        | —           | все в UI                             | `quantity` (услуга всегда `0`)              |

Подсказка у единицы: «Цена закупки и цена продажи указываются за 1 {unit}».

**Поштучная продажа.** Выключение очищает список упаковок. Включение — кнопка «Добавить упаковку».

Строка упаковки:

| Поле UI               | API                   | Правила                       |
| --------------------- | --------------------- | ----------------------------- |
| Название              | `name`                | trim, пустые строки отбросить |
| Количество в упаковке | `quantity_in_package` | > 0, иначе 1                  |
| Цена за штуку         | `piece_unit_price`    | строка, `>= 0`, до 3 знаков   |
| —                     | `unit`                | копировать единицу товара     |

Валидация: если поштучная включена, у каждой именованной упаковки qty > 0 и цена за штуку заполнена (`>= 0`).

**18+.** При включении — info-диалог: «Этот товар предназначен для совершеннолетних». Под чекбоксом текст: на кассе уведомление, на втором экране «Вам есть 18?».

**Количество** в UI помечено `*`, но клиентская валидация пустое пропускает → в API уходит `0`.

### 6.4. Цены (товар)

| UI                       | id          | Обязательно | API                               |
| ------------------------ | ----------- | ----------- | --------------------------------- |
| Цена закупки (за 1 unit) | —           | да          | `purchase_price`                  |
| Наценка %                | `markup`    | нет         | `markup_percent`, пусто → `"0"`   |
| Цена продажи (за 1 unit) | —           | да          | `price`, пусто → `"0"`            |
| Оптовая цена             | `wholesale` | нет         | `wholesale_price`, пусто → `"0"`  |
| Скидка %                 | `discount`  | нет         | `discount_percent`, пусто → `"0"` |

Ввод цен: только цифры и одна точка, **макс. 3 знака** после запятой.

Авторасчёт (§9.2):

- меняется закупка или наценка → `price = purchase * (1 + markup/100)`, округление до **2** знаков, флаг «цену трогали руками» сбросить
- пользователь меняет цену продажи → пересчитать наценку: `markup = (price/purchase - 1) * 100`, округление до 2 знаков

### 6.5. Цены (услуга)

Только цена продажи (`*`) и скидка. `purchase_price` в API всегда `"0"`, `quantity` всегда `0`, `stock` всегда `false`.

### 6.6. Склад (только товар)

| UI             | id         | API               | Примечание                                       |
| -------------- | ---------- | ----------------- | ------------------------------------------------ |
| Поставщик      | `supplier` | `client`          | uuid или `null`. Селект + «+ Создать поставщика» |
| Долг по товару | `debt`     | не поле товара    | отдельный POST deals / debts, §13                |
| Мин. остаток   | `minStock` | —                 | **не отправлять**, в API нет                     |
| Страна         | `country`  | `country`         | русское имя из списка стран                      |
| Срок годности  | `expiry`   | `expiration_date` | `YYYY-MM-DD` или `null`                          |

Поставщики: `GET /main/clients/`, фильтр `type == "suppliers"`. В селекте `full_name`, value = `id`.

Создание поставщика `POST /main/clients/`:

```json
{
  "full_name": "",
  "phone": "",
  "email": "",
  "date": "2026-08-12",
  "type": "suppliers",
  "llc": "",
  "inn": "",
  "okpo": "",
  "score": "",
  "bik": "",
  "address": ""
}
```

Поля формы: ФИО, ОсОО, ИНН, ОКПО, Р/СЧЁТ, БИК, Адрес, Телефон, Почта. После успеха — выбрать созданного, закрыть форму.

Страна: searchable dropdown, хранить **имя** (`"Кыргызстан"`), не ISO-код. Список как на вебе (`src/shared/config/data/countries.ts`).

### 6.7. Акция (только товар)

id раскладки: `promotion`.

Чекбокс «Акционный товар» → API `stock: true|false`.

Если включено — таблица ступеней (до **30**):

| Колонка               | API                | Правила                |
| --------------------- | ------------------ | ---------------------- |
| Сумма строки от (сом) | `min_amount`       | ≥ 0, строка            |
| Скидка %              | `discount_percent` | 0.01–100               |
| Лимит шт. (необяз.)   | `promo_quantity`   | целое ≥ 1 или не слать |

Подсказка: «Скидка по ступеням от суммы строки в чеке (цена × количество)».

В API уходит `promotion_rules_input` (и веб дублирует логику `promotion_rules` не шлёт отдельно — канон: **`promotion_rules_input`**). Невалидные строки отбросить. `position` = 0..n-1 после сортировки. Если акция выключена — `stock: false`, `promotion_rules_input: []`.

При включении чекбокса, если ступеней нет — сразу одна пустая строка.

### 6.8. PLU

id: `plu`. Блок виден **только** если весовой товар или дробная услуга.

Tooltip: PLU для весов с печатью этикетки. Формат штрихкода весов: `undefined PPPPP WWWWW S`, где PPPPP — PLU, WWWWW — вес в тысячных, S — контрольная сумма.

В API: число или `null`. Если весовой и поле пустое — `weightProductsCount + 1`.

### 6.9. Характеристики и описание

id: `characteristics`, `description`.

| UI                  | API `characteristics`                          |
| ------------------- | ---------------------------------------------- |
| Высота, см          | `height_cm`                                    |
| Ширина, см          | `width_cm`                                     |
| Глубина, см         | `depth_cm`                                     |
| Фактический вес, кг | `factual_weight_kg`                            |
| Описание (textarea) | `description` + дубль в корневом `description` |

`"0"` и пустое → в объекте `null`. Если все габариты null и описание пустое — слать `characteristics: null`.

### 6.10. Комплект

Обязательно ≥ 1 товар в составе.

Пикер: `GET /main/products/list/?page_size=500&kind=product`. В состав можно добавить только `kind=product` с остатком `quantity > 0`. Исключить сам редактируемый товар и уже добавленные.

У каждой позиции: имя, количество (≥ 1), кнопка удалить.

Цена комплекта считается автоматически:

```
price = Σ (component.price * component.quantity)
```

округление до 2 знаков. Пользователь может поправить вручную.

В API состав уходит **не отдельным полем**, а внутри `packages_input`:

```json
{
  "name": "Хлеб",
  "quantity_in_package": 2,
  "unit": "шт",
```

## 8. Раскладка формы (как Control Center)

Одна раскладка **на компанию**. Кассир на другом устройстве видит ту же упрощённую форму.

### 8.1. Кто может настраивать

`role == owner || role == admin`. Остальные только **применяют** `hidden[]` с сервера, кнопки настройки нет.

### 8.2. API

```
GET  /main/products/form-layout/
PATCH /main/products/form-layout/
```

GET: любой сотрудник компании. Нет записи → `{ "hidden": [] }`.

PATCH: только owner/admin, иначе 403. Body:

```json
{ "hidden": ["images", "characteristics", "expiry"] }
```

Последний PATCH побеждает (без merge). `[]` = полная форма. Неизвестные id отбросить, не 400.

Допустимые id:

```
code, barcode, alternateBarcodes, article, hotkey, images,
category, brand,
unit, pieceSale, weight, adult, packaging,
markup, wholesale, discount,
supplier, debt, minStock, country, expiry,
promotion, characteristics, description, plu
```

### 8.3. Поведение клиента

1. Сразу читать локальный кэш: ключ `market_product_form_layout_{companyId}` → `{ "hidden": [...] }`.
2. Параллельно GET. Успех → заменить кэш и UI. `404`/`405`/`501` → остаться на кэше, **без тоста**.
3. Owner/admin: «Настроить форму» → на каждом скрываемом блоке красный «−».
4. «Добавить поле» — bottom sheet со скрытыми полями, сгруппированными:
   - Основное
   - Классификация
   - Единицы и флаги
   - Цены
   - Склад
   - Дополнительно

5. «Сбросить» → `hidden: []`.
6. «Готово» → выйти из режима, PATCH.
7. Каждое изменение: сразу в кэш, PATCH с debounce 500 мс.
8. Ошибка PATCH (кроме missing endpoint) — тост: «Не удалось сохранить раскладку формы на сервер. На этом устройстве она останется.» Локальный кэш **не откатывать**.

Метаданные блоков (лейбл + описание) — как в `PRODUCT_FORM_BLOCK_META` на вебе.

### 8.4. Правило видимости (важно)

Скрытое поле **всё равно показать**, если в текущей карточке оно уже заполнено. Иначе при редактировании пропадут акция / 18+ / фото.

| id                                               | «Заполнено», если                                                            |
| ------------------------------------------------ | ---------------------------------------------------------------------------- |
| `barcode`                                        | непусто                                                                      |
| `alternateBarcodes`                              | непусто                                                                      |
| `article`                                        | непусто                                                                      |
| `hotkey`                                         | непусто                                                                      |
| `images`                                         | есть фото                                                                    |
| `category` / `brand`                             | имя непусто                                                                  |
| `pieceSale`                                      | флаг вкл. или есть упаковки                                                  |
| `weight`                                         | весовой / дробная услуга                                                     |
| `adult`                                          | 18+                                                                          |
| `packaging`                                      | есть упаковки                                                                |
| `wholesale`                                      | оптовая непуста                                                              |
| `supplier`                                       | выбран поставщик                                                             |
| `debt`                                           | открыта форма долга                                                          |
| `country`                                        | страна выбрана                                                               |
| `expiry`                                         | дата есть                                                                    |
| `promotion`                                      | есть ступени                                                                 |
| `characteristics`                                | любой габарит ≠ 0                                                            |
| `description`                                    | непусто                                                                      |
| `plu`                                            | непусто                                                                      |

## 9. Клиентские алгоритмы

### 9.1. Генерация EAN-13

12 случайных цифр + контрольная сумма:

- позиции 1,3,5,7,9,11 (0-based чётные) × 1
- позиции 2,4,6,8,10,12 (0-based нечётные) × 3
- `checksum = (10 - (sum % 10)) % 10`

Кнопка «(Сгенерировать)» перезаписывает поле.

### 9.2. Цена продажи

```
selling = purchase * (1 + markup / 100)
price   = (selling * 100).round() / 100
```

Обратно:

```
markup = ((selling / purchase) - 1) * 100
markup = (markup * 100).round() / 100
```

Если закупка = 0 и наценка = 0 → очистить цену продажи.

### 9.3. Нормализация чисел

- Ввод: заменить `,` → `.`, выкинуть всё кроме цифр и точки, обрезать дробную часть до 3 знаков.
- В API проценты и цены — **строки**.
- Количество: `Number(quantity)` или `0`.

## 11. Порядок после успешного сохранения

Строго после 200 create/PATCH. Ошибки шагов 2–4 **не откатывают** товар.

```
2. rememberAdultProduct (локальный кэш 18+)
```

## 12. Изображения

Не в теле товара. После появления `productId`:

**Удаление (только edit):** сравнить исходные `images[].id` с текущим списком. Ушедшие:

```
DELETE /main/products/{productId}/images/{imageId}/
```

Параллельно, `Promise.allSettled` — ошибка одного не стопорит остальные.

**Загрузка новых** (есть локальный файл, нет серверного id):

```
POST /main/products/{productId}/images/
Content-Type: multipart/form-data

image: <file>
alt: <имя товара, если alt пустой>
is_primary: "true" | "false"
```

Первое добавленное фото — главное, пока пользователь не выберет другое. Удаление главного → главное становится первое оставшееся.

В edit существующие фото: `file = null`, `preview = image_url`, хранить `id`. При дублировании URL можно показать, но **id не хранить** (иначе DELETE снесёт фото оригинала). Новые файлы при дубле залить как у нового товара.

Ошибка загрузки — `console.warn` / тихий лог, товар уже сохранён.

## 13. Долг, предоплата, касса

Включаются чекбоксом «Добавить долг по этому товару» (блок `debt`). Без выбранного поставщика — красный текст «Выберите поставщика в форме выше!».

`totalAmount = purchase_price * quantity` (для услуги = 0).

### 13.1. Тип «Долги»

`POST /main/clients/{clientId}/deals/`

```json
{
  "title": "Долг Иванов",
  "kind": "debt",
  "amount": "1440.00",
  "note": "",
  "client": "<uuid>",
  "debt_months": 3,
  "auto_schedule": true
}
```

`kind` из русского статуса: «Долги» → `debt`, «Предоплата» → `prepayment`, иначе `sale`. Суммы в deals — строки с 2 знаками (`toFixed(2)`).

Тариф **«Старт»** дополнительно:

```
POST /main/debts/
{ "name": "Иванов", "phone": "+996…", "due_date": "2026-09-12", "amount": 1440 }
```

И в UI долга на «Старт»: телефон поставщика + дата оплаты.

### 13.2. Тип «Предоплата»

Тот же deals, `kind: "prepayment"`, плюс `"prepayment": "500.00"`. Поля UI: сумма предоплаты + срок долга (мес.).

### 13.3. Поставщик без долга

Если `client` выбран, а чекбокс долга выключен:

```json
{
  "title": "<имя товара>",
  "kind": "sale",
  "amount": "1440.00",
  "note": "",
  "client": "<uuid>"
}
```

Вместо этого передать `payment_type` / `cashflow_amount` в сам create, см. [cashflows-backend-only.md §3.1](./cashflows-backend-only.md#31-создание-товара). Текст ниже оставлен только для истории.

Только **создание**, и только если тип оплаты **не** «Долги».

```
GET  /construction/cashboxes/
POST /construction/cashflows/
```

```json
{
  "cashbox": "<uuid первой кассы>",
  "type": "expense",
  "name": "Молоко 2.5% 1л",
  "amount": 1440,
  "source_cashbox_flow_id": "<id созданного товара>",
```

`status`: тариф «Старт» → `"approved"`, иначе `"pending"`.

## 15. Вкладка «Сканирование» (только создание)

Не полная форма, а быстрый приход по штрихкоду.

1. Ждать скан (hardware wedge / `mobile_scanner`). Мин. длина 3. Если фокус в input — скан игнорировать.
2. `GET /main/products/global-barcode/{code}/`  
   404 → «Товар с таким штрих-кодом не найден».
3. Prefill: name, price, purchase_price, wholesale_price, plu, scale_type.
4. Пользователь правит количество, цены, наценку, поставщика, акцию, долг, доп. коды.
5. Сохранение:

```
POST /main/products/create-by-barcode/
```

Тело: `barcode` + поля формы (`name`, `quantity`, `price`, `wholesale_price`, `purchase_price`, `markup` как `markup_percent`, `plu`, `scale_type`, `client`, `alternate_barcodes`, `stock`, `promotion_rules_input`).

Дальше те же deals / cashflow, что у ручного создания. Картинок и полной карточки на этой вкладке нет.

Для сферы «склад» (не маркет) веб бьёт в `POST /warehouse/{uuid}/products/scan/` с обязательными `category` и `warehouse`. Маркет-приложение Flutter это **не** использует.
